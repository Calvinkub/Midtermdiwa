📘 Week 1 · Word Representation
1ออกบ่อยPMI & PPMI
จากคลังข้อความมีคู่คำที่ปรากฏร่วมกันทั้งหมด N = 1000 ครั้ง จงหา PMI และ PPMI ของคู่ (w, c)
กำหนดให้
(ก) count(w,c)=30, count(w)=100, count(c)=150  ·  (ข) count(w,c)=5, count(w)=100, count(c)=150
ดูเฉลยทีละ step
1แปลง count เป็นความน่าจะเป็น (หารด้วย N)(ก) P(w,c)=30/1000=0.03 · P(w)=0.1 · P(c)=0.15
2แทนในสูตร PMI = log₂[ P(w,c) / (P(w)·P(c)) ]= log₂[ 0.03 / (0.1 × 0.15) ] = log₂[ 0.03 / 0.015 ] = log₂(2)
3log₂(2) = 1.0 → เป็นบวก → PPMI = max(1.0, 0) = 1.0
4ข้อ (ข): P(w,c)=0.005 → ratio = 0.005/0.015 = 0.333 → log₂(0.333) = −1.585PMI ติดลบ → PPMI = max(−1.585, 0) = 0
คำตอบ
(ก) PMI = 1.0, PPMI = 1.0  ·  (ข) PMI = −1.585, PPMI = 0
2ออก 3 ข้อBPE — การ merge ครั้งแรก
คลังคำ (พร้อมความถี่) จงหาว่า BPE จะ merge คู่ไหนเป็นอันดับแรก
กำหนดให้
hug:10 · pug:5 · pun:12 · bun:4 · hugs:5 (แตกเป็นตัวอักษรก่อน)
ดูเฉลยทีละ step
1BPE = รวมคู่ที่ ปรากฏบ่อยที่สุด → นับความถี่ของทุกคู่ที่ติดกัน (คูณความถี่ของคำ)
2ไล่นับคู่หลักๆ(u,g): hug10 + pug5 + hugs5 = 20 (p,u): pug5 + pun12 = 17 (u,n): pun12 + bun4 = 16 (h,u): hug10 + hugs5 = 15
3คู่ที่บ่อยที่สุดคือ (u, g) = 20 → merge เป็น token ใหม่ ug
คำตอบ
merge คู่ (u, g) → "ug" (ความถี่ 20)
กับดัก: ถ้าเป็น WordPiece จะไม่เลือกจากความถี่ แต่เลือกจาก likelihood (ดูข้อ 3)
3คำนวณWordPiece — เลือกคู่ที่ score สูงสุด
WordPiece merge คู่ที่ได้ score = count(AB) / (count(A)·count(B)) สูงสุด จงหาว่าจะ merge คู่ไหน
กำหนดให้
(e,r): count(er)=6, count(e)=10, count(r)=6 · (s,t): count(st)=9, count(s)=9, count(t)=15 · (l,o): count(lo)=7, count(l)=7, count(o)=20
ดูเฉลยทีละ step
1คำนวณ score ของแต่ละคู่(e,r) = 6 / (10×6) = 6/60 = 0.100 (s,t) = 9 / (9×15) = 9/135 = 0.067 (l,o) = 7 / (7×20) = 7/140 = 0.050
2เลือก score สูงสุด → (e, r) = 0.100
คำตอบ
WordPiece merge (e, r) — แม้ (s,t) จะบ่อยกว่า (9 > 6) ก็ตาม
จุดสำคัญ: BPE จะเลือก (s,t) เพราะบ่อยสุด แต่ WordPiece เลือก (e,r) เพราะ likelihood สูงสุด
📗 Week 2 · RNN / LSTM / GRU
4ออกบ่อยPerplexity
(ก) โมเดลให้ความน่าจะเป็นของแต่ละคำในประโยค 3 คำ จงหา perplexity   (ข) ถ้า average cross-entropy loss = 2.0 nats หา PPL
กำหนดให้
(ก) P = [0.5, 0.25, 0.125]
ดูเฉลยทีละ step
1สูตร PPL = (Π pᵢ)^(−1/N) = exp( −(1/N) Σ ln pᵢ )
2คูณความน่าจะเป็น (N=3)Π p = 0.5 × 0.25 × 0.125 = 0.015625 = 1/64
3ยกกำลัง −1/3PPL = (1/64)^(−1/3) = 64^(1/3) = 4
4ข้อ (ข): PPL = e^J = e² ≈ 7.389 (ถ้า loss เป็น bits ใช้ 2^J แทน)
คำตอบ
(ก) PPL = 4  ·  (ข) PPL = e² ≈ 7.39 · จำ: ยิ่งต่ำยิ่งดี, PPL=k = งงเท่ากับเดาจาก k คำ
5คำนวณGradient Clipping
gradient vector g = [6, 8] และ threshold τ = 5 จงหา gradient หลัง clipping
ดูเฉลยทีละ step
1หา norm‖g‖ = √(6² + 8²) = √(36+64) = √100 = 10
2เช็คเงื่อนไข: 10 > τ (=5) → ต้อง clip (ถ้า ≤ τ ไม่ต้องทำอะไร)
3สเกลด้วย τ/‖g‖g ← g × (5/10) = [6, 8] × 0.5 = [3, 4]
4ตรวจ: ‖[3,4]‖ = √(9+16) = 5 ✓ (เท่ากับ τ พอดี)
คำตอบ
g_clipped = [3, 4] (norm = 5) · แก้ปัญหา exploding gradient เท่านั้น
6ออก 3 ข้อLSTM — อัปเดต Cell State & Hidden
จงคำนวณ cell state ใหม่ (cₜ) และ hidden state (hₜ)
กำหนดให้
forget f=0.8 · input i=0.6 · output o=0.5 · candidate g=1.0 · cₜ₋₁=1.5
ดูเฉลยทีละ step
1อัปเดต cell state cₜ = fₜ⊙cₜ₋₁ + iₜ⊙gₜcₜ = (0.8 × 1.5) + (0.6 × 1.0) = 1.2 + 0.6 = 1.8
2คำนวณ hidden state hₜ = oₜ⊙tanh(cₜ)tanh(1.8) ≈ 0.9468
3คูณด้วย output gatehₜ = 0.5 × 0.9468 ≈ 0.4734
คำตอบ
cₜ = 1.8  ·  hₜ ≈ 0.473 · (forget ตัดของเก่า, input เติมของใหม่ด้วยการ บวก = ทางด่วน gradient)
📙 Week 3 · Seq2Seq & Attention
7คำนวณClipped Precision (BLEU)
candidate = "the the the the the the the" (7 คำ) · reference = "the cat is on the mat" จงหา unigram clipped precision
ดูเฉลยทีละ step
1นับ "the" ใน candidate = 7
2นับ "the" ที่มีจริงใน reference = 2 (max count)
3clip: นับได้ไม่เกินที่ reference มี → min(7, 2) = 2
4precision = clipped / total candidate= 2 / 7 ≈ 0.286
คำตอบ
Clipped precision = 2/7 ≈ 0.286 (ถ้าไม่ clip จะได้ 7/7=1.0 → นี่คือเหตุผลที่ต้อง clip กันโมเดลโกงด้วยการพูดซ้ำ)
8ออกบ่อยBLEU เต็มสูตร (BP + precisions)
จงคำนวณ BLEU-4 (น้ำหนักเท่ากัน wₙ = 1/4)
กำหนดให้
ความยาว candidate c=9, reference r=10 · p₁=0.8, p₂=0.6, p₃=0.45, p₄=0.30
ดูเฉลยทีละ step
1หา Brevity Penalty — เพราะ c(9) < r(10) จึงใช้ expBP = exp(1 − r/c) = exp(1 − 10/9) = exp(−0.1111) ≈ 0.8949
2รวม log ของ precision (คูณน้ำหนัก 1/4)Σ wₙ ln pₙ = 0.25×(ln0.8 + ln0.6 + ln0.45 + ln0.30) = 0.25×(−0.2231 −0.5108 −0.7985 −1.2040) = 0.25×(−2.7364) = −0.6841
3exp กลับexp(−0.6841) ≈ 0.5045
4คูณ BPBLEU = 0.8949 × 0.5045 ≈ 0.4515
คำตอบ
BLEU ≈ 0.451 (หรือ 45.1%)
9คำนวณTemperature Softmax
logits z = [2, 1, 0] จงหา distribution ที่ T=1 และ T=0.5 แล้วเปรียบเทียบ
ดูเฉลยทีละ step
1สูตร pᵢ = softmax(zᵢ/T) = e^(zᵢ/T) / Σ e^(zⱼ/T)
2T=1: e^z = [e², e¹, e⁰] = [7.389, 2.718, 1.0], รวม = 11.107p = [0.665, 0.245, 0.090]
3T=0.5: z/T = [4, 2, 0] → e^ = [54.60, 7.389, 1.0], รวม = 62.99p = [0.867, 0.117, 0.016]
คำตอบ
T=1 → [0.665, 0.245, 0.090] · T=0.5 → [0.867, 0.117, 0.016]
T ต่ำ → distribution คมขึ้น (มั่นใจตัวที่ prob สูงมากขึ้น) · T สูง → แบนลง (มั่วขึ้น)

10ออกบ่อยScaled Dot-Product Attention (เต็มขั้นตอน)
คำนวณ context vector ของ 1 query
กำหนดให้
q=[1,1] · k₁=[1,0], k₂=[0,2] · v₁=[2,0], v₂=[0,4] · dₖ=2
ดูเฉลยทีละ step
1คะแนนดิบ = q·kᵢq·k₁ = 1×1 + 1×0 = 1 · q·k₂ = 1×0 + 1×2 = 2
2หารด้วย √dₖ = √2 ≈ 1.414scaled = [1/1.414, 2/1.414] = [0.707, 1.414]
3softmaxe^0.707=2.028, e^1.414=4.113, รวม=6.141 α = [0.330, 0.670]
4context = Σ αᵢ·vᵢ= 0.330×[2,0] + 0.670×[0,4] = [0.660, 2.679]
คำตอบ
context ≈ [0.66, 2.68] · หาร √dₖ เพื่อคุม variance ให้ softmax ไม่อิ่มตัว
11คำนวณPositional Encoding
จงหาเวกเตอร์ positional encoding ที่ตำแหน่ง pos=1 เมื่อ d_model=4
ดูเฉลยทีละ step
1สูตร PE(pos,2i)=sin(pos/10000^(2i/d)), ดัชนีคี่ใช้ cos · d=4 มี i=0,1
2i=0 → เลขชี้กำลัง 2i/d = 0 → 10000⁰ = 1 → มุม = 1/1 = 1PE(1,0)=sin(1)=0.8415 · PE(1,1)=cos(1)=0.5403
3i=1 → 2i/d = 0.5 → 10000^0.5 = 100 → มุม = 1/100 = 0.01PE(1,2)=sin(0.01)=0.0100 · PE(1,3)=cos(0.01)=1.0000
คำตอบ
PE(pos=1) = [0.842, 0.540, 0.010, 1.000] · แต่ละมิติมีความถี่ต่างกัน (คู่=sin, คี่=cos)
12คำนวณMulti-Head Dims + Attention Params
d_model=512, จำนวนหัว h=8 · จงหา (ก) dₖ ต่อหัว (ข) จำนวนพารามิเตอร์ของ attention ต่อ 1 layer
ดูเฉลยทีละ step
1มิติต่อหัว dₖ = d_model / h = 512 / 8 = 64
2มี 4 เมทริกซ์ Wq, Wk, Wv, Wo แต่ละตัวขนาด d_model×d_modelparams = 4 × d_model² = 4 × 512² = 4 × 262,144
3= 1,048,576 ≈ 1.05M พารามิเตอร์
คำตอบ
(ก) dₖ = 64  ·  (ข) 4·d² = 1,048,576 ≈ 1.05M · (LLaMA-7B d=4096 → 4·4096² ≈ 67.1M/layer)
13คำนวณFFN Parameter Count
Feed-Forward Network มี d_model=512, d_ff=2048 · จงหาจำนวนพารามิเตอร์ (นับ bias ด้วย)
ดูเฉลยทีละ step
1FFN = 2 ชั้น linear: W₁ (d_model→d_ff) แล้ว W₂ (d_ff→d_model)
2น้ำหนักW₁ = 512×2048 = 1,048,576 W₂ = 2048×512 = 1,048,576 → รวม = 2,097,152
3bias: b₁ = 2048, b₂ = 512 → รวม 2,560total = 2,097,152 + 2,560 = 2,099,712
คำตอบ
≈ 2.1M พารามิเตอร์ (weight 2·d·d_ff = 2,097,152 + bias 2,560) · ปกติ d_ff = 4×d_model
📓 Week 5 · Transformer Decoder · KV Cache ⭐
14⭐ ออก 5 ข้อKV Cache Memory — MHA
จงคำนวณขนาด KV cache (MB) สำหรับ Multi-Head Attention
กำหนดให้
batch B=4 · seq=2048 · n_kv_heads=32 · head_dim=128 · n_layers=32 · FP16 = 2 bytes
ดูเฉลยทีละ step
1สูตร bytes = 2 × B × seq × n_kv_heads × head_dim × n_layers × bytes_per_param (เลข 2 = เก็บทั้ง K และ V)
2นับจำนวน element ก่อน2 × 4 × 2048 × 32 × 128 × 32 = 2,147,483,648 elements
3คูณ bytes ต่อ element (FP16 = 2)= 2,147,483,648 × 2 = 4,294,967,296 bytes
4แปลงเป็น MB (หาร 1024²)= 4,294,967,296 / 1,048,576 = 4096 MB
คำตอบ
KV cache (MHA) = 4096 MB = 4 GB · (n_kv_heads×head_dim = 32×128 = 4096 = d_model)
15⭐ ออก 5 ข้อKV Cache — GQA เทียบ MHA
ใช้ค่าเดิมจากข้อ 14 แต่เปลี่ยนเป็น GQA n_kv_heads=8 · จงหาขนาด cache และอัตราส่วนที่ประหยัดได้
ดูเฉลยทีละ step
1เปลี่ยนแค่ n_kv_heads: 32 → 8 (ตัวอื่นเท่าเดิม)
2เพราะ cache แปรผันตรงกับ n_kv_heads → คำนวณง่ายๆจากอัตราส่วนGQA = MHA × (8/32) = 4096 × (1/4) = 1024 MB
3อัตราส่วนประหยัด = 32/8 = 4 เท่า
คำตอบ
KV cache (GQA-8) = 1024 MB = 1 GB → เล็กลง 4 เท่า · (MQA = 1 head จะเล็กสุด)
กับดัก: "GQA เพิ่มขนาด KV cache" = ผิด → GQA/MQA ลด cache
16คำนวณStatic Weights + Total VRAM
โมเดล 7B parameters โหลดแบบ FP16 · จงหา (ก) ขนาด static weights (ข) VRAM รวมเมื่อรวม KV cache จากข้อ 14
ดูเฉลยทีละ step
1Static = params × bytes= 7×10⁹ × 2 = 14×10⁹ bytes ≈ 14 GB
2VRAM รวม = static + KV cache (+ activations)≈ 14 GB + 4 GB = 18 GB
3static คงที่ แต่ KV cache โตตาม seq & batch → ยาว/ใหญ่เกินไป = CUDA OOM
คำตอบ
(ก) static ≈ 14 GB  ·  (ข) รวม ≈ 18 GB (การ์ด 16GB จะ OOM)
17คำนวณTop-k vs Top-p (Nucleus)
distribution เรียงลำดับ: [0.4, 0.25, 0.15, 0.10, 0.06, 0.04] · จงหาว่า (ก) top-k k=2 (ข) top-p p=0.9 เก็บ token ใดบ้าง
ดูเฉลยทีละ step
1Top-k (k=2): เก็บ 2 ตัวแรกที่ prob สูงสุด → {0.4, 0.25} แล้ว renormalize (÷0.65)→ [0.615, 0.385]
2Top-p (p=0.9): บวกสะสมจนถึง ≥ 0.90.4 → 0.65 → 0.80 → 0.90 (ครบที่ตัวที่ 4)
3เก็บ 4 ตัวแรก {0.4, 0.25, 0.15, 0.10} แล้ว renormalize
คำตอบ
(ก) top-k=2 → เก็บ 2 ตัว  ·  (ข) top-p=0.9 → เก็บ 4 ตัว
Top-p ปรับจำนวนตามความชัน (adaptive), Top-k คงที่เสมอ · ลำดับกรอง: temperature → top-k → top-p → sample

20คำนวณChinchilla Scaling Law
ตาม Chinchilla (~20 tokens ต่อ 1 parameter) · (ก) โมเดล 70B ต้องเทรนด้วยกี่ token (ข) FLOPs โดยประมาณ (C≈6·N·D)
ดูเฉลยทีละ step
1จำนวน token = params × 20D = 70×10⁹ × 20 = 1.4×10¹² = 1.4T tokens
2FLOPs ≈ 6·N·D= 6 × (7×10¹⁰) × (1.4×10¹²) ≈ 5.88×10²³ FLOPs
คำตอบ
(ก) 1.4T tokens  ·  (ข) ≈ 5.9×10²³ FLOPs
กับดัก: "Kaplan บอก 20 tok/param" = ผิด → นี่คือ Chinchilla (Kaplan บอกให้ขยายโมเดลเร็วกว่า data)
